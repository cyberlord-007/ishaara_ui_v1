## Ishaara conventions

Full detail in `docs/implementation_plan.md`. Read it before writing code.

- Work the milestones (F0-F8) in order; a milestone is done only when every acceptance check passes.
- `GET /openapi.json` is the source of truth for wire shapes over this plan. Disagreements go in `docs/DECISIONS.md`. In practice, `docs/postman/ishaara.postman_collection.json` (a real, tested Postman collection — saved example responses plus `pm.test` assertions on every request) is the actual verified contract available in this repo; treat its examples and assertions as ground truth over this plan's own "inferred" shapes.
- A schema field the real backend doesn't send yet is modeled as **optional**, never deleted outright and never silently invented — add it to the relevant Zod schema as `.optional()`, make the UI fall back gracefully when it's absent, and log the ask in `docs/backend-requests.md` (what's needed, why, proposed shape). This way the frontend starts using it the moment the backend adds it, with no further schema change.
- `video_key` encodes the YouTube video id and narration language (`{youtube_id}_{language}_v{pipeline_version}`) — the backend does not return either as a separate field anywhere. Use `parseVideoKey()` (`src/lib/videoKey.ts`) to recover them; don't add `youtube_video_id`/`narration_language` fields to a response schema expecting the backend to supply them.
- A resource that needs the bearer token but is consumed by an element that can't send headers itself (`<track src>`, unlike `<audio src>` which fetches cue audio from a public unauthenticated URL) is fetched as a `Blob` (`apiRequestBlob` in `client.ts`) and turned into a blob URL with `URL.createObjectURL`, cached by a TanStack Query hook (see `useCuesVtt` in `hooks.ts`) — the query's `gcTime` owns the blob URL's lifetime, not an explicit `revokeObjectURL` call.
- Never call `fetch` outside `src/lib/api/`; components and hooks use the typed client only.
- Never touch the YouTube IFrame API outside `src/features/player/youtube/`; the player machine talks to it through `VideoPlayerPort`.
- Every interactive element is a real HTML control (`button`, `a`, `input`, `select`). No `div onClick`, no positive `tabindex`.
- Every user-visible string lives in `src/messages/{en,hi}.json`. No hard-coded copy in components.
- Secrets and config come from `NEXT_PUBLIC_*` env vars validated at boot by `src/env.ts`. Never commit `.env.local`.
- Commit after each milestone with message `feat(fN): <summary>`.
- TypeScript strict plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`. No `any`; narrow `unknown`.
- Types derive from Zod schemas with `z.infer`/`z.output`; never hand-write a type that duplicates a schema.
- Server Components by default; add `"use client"` only to the leaf that needs state, effects or browser APIs.
- Names say what things are (`videoKey`, `cueStartSeconds`); no `data`, `res`, `tmp`, `item` outside a two-line callback.
- Components stay under ~120 lines, hooks under ~60. Pure logic lives in plain functions with unit tests.
- TSDoc on every exported function, hook and component: what it does, params, return, what it throws.
- Biome is the one lint/format tool; a11y rules are errors.
- Definition of done for every milestone: `bun run typecheck`, `bun run lint`, `bun run test`, `bun run build`. (Playwright/axe E2E, `bun run test:a11y` in the plan, is deliberately not wired up yet.)
- Design tokens live in `src/styles/tokens.css` as Tailwind v4 `@theme` values (`bg-surface`, `text-ink`, `rounded-panel`, etc.), re-pointed per theme via `[data-theme]` selectors and `prefers-color-scheme`/`forced-colors` media queries. `src/styles/tokens.test.ts` parses this file directly and checks contrast — don't duplicate token values elsewhere as literals.
- The highlighter mark (`--color-highlighter`, `#FFD43B`) is the same colour in every theme, so text painted on it must always be a fixed dark ink (`#0f1c3f`), never `text-ink`/`--color-ink` — that token goes near-white in dark mode.
- A form field built on React Aria Components (`TextField`, `RadioGroup`, …) wires to React Hook Form with `Controller`, not `register()` — RAC's `onChange` hands back a value, not an event, so `register()`'s event-shaped handlers don't fit.
- `router.push`/`replace` only accept the app's known static routes as literal strings (Next's typed-routes codegen, `.next/types/routes.d.ts`) or a `UrlObject`; a dynamically computed path (e.g. a `?next=` redirect target) needs `import type { Route } from "next"` and an explicit `as Route` cast — there's no generic escape hatch for computed strings.
- Same cast for `<Link href={item.href}>` when `item.href` comes from `.map()` over an array of route literals (see `Header.tsx`'s `NAV_ITEMS`): TypeScript infers `Link`'s generic from one union member and then rejects the others, even though each is individually a valid static route. `bun run typecheck`'s standalone `next typegen` doesn't always catch this — `next build`'s own type-check pass does, so don't treat a clean `typecheck` run alone as proof a nav array is fine.
- Any component calling `useSearchParams()` must be wrapped in `<Suspense>` (see `AuthGate`, `sign-in/page.tsx`) — required for `output: 'export'` to prerender the route.
- `usePreferencesStore` uses Zustand's `persist` with `skipHydration: true`; something must call `usePreferencesStore.persist.rehydrate()` once after mount (done in `providers/PreferencesEffects.tsx`) so the server/first-client render stay in sync before localStorage values apply.
- File names mirror the casing of what they export: PascalCase for a file whose primary export is a React component (`AuthGate.tsx`, `Header.tsx`, `QueryProvider.tsx`), camelCase for a hook, store, machine or plain utility module (`useFocusOnMount.ts`, `preferencesStore.ts`, `youtubeUrl.ts`, `cueIndex.ts`, `narratedPlayerMachine.ts`). Next.js's reserved file names (`page.tsx`, `layout.tsx`, `not-found.tsx`) and route-segment directory names (`sign-in/`, which is also the URL) are exempt — don't rename those. **This overrides `docs/implementation_plan.md`'s own repo-layout file names wherever they're kebab-case** (e.g. the plan writes `cue-index.ts`, `narrated-player.machine.ts`, `youtube-player-port.ts`, `load-iframe-api.ts`, `narration-audio.ts` — use `cueIndex.ts`, `narratedPlayerMachine.ts`, `youtubePlayerPort.ts`, `loadIframeApi.ts`, `narrationAudio.ts` instead). The plan is authoritative for behavior and shapes, not for file-name casing.
- `useFocusOnMount`/`useDocumentTitle` must be called inside the component that actually renders the target `h1`, not in an ancestor — e.g. inside `AuthGate`'s `children`, not in the page component that passes `children` to it. `AuthGate` may render its own loading state on first mount instead, so a ref/effect set up any higher never sees the real heading. Every current page follows this via a small `*Content` inner component (see `page.tsx`, `library/page.tsx`, `settings/page.tsx`, `me/page.tsx`).
- Every route-change auto-focus target (`<h1 ref={headingRef} tabIndex={-1}>`) also needs the `route-heading` class (`globals.css`). Without it, most browsers' `:focus-visible` heuristic matches script-triggered `.focus()`, so the global focus ring rings the heading on every page load for mouse/touch users — safe to suppress only here because `tabIndex={-1}` means Tab can never reach it anyway.
- `components/ui/TextField` forwards its `ref` to the underlying `<input>`; a `Controller`-based field must pass `ref={field.ref}` through to it, or React Hook Form's `setFocus("fieldName")` silently does nothing (no DOM node is registered). On an invalid submit, call `setFocus` on the first invalid field — don't rely on the inline `FieldError` text alone to get a sighted or screen-reader user there.
- A toast (`components/ui/Toast`'s `toastQueue`) is a non-blocking *addition*, never the only place an error appears — pair it with the existing inline error/`role="alert"` block, not instead of it (see `LinkForm`'s `onInvalid`).
- Never give a Zod-validated `TextField` a native-constraint `type` (`"url"`, `"email"`, …) unless its `<form>` also has `noValidate`. The browser's own constraint validation runs *before* the submit event reaches React and silently blocks the whole thing for input that fails the native check (e.g. plain text in a `type="url"` field) — React Hook Form's resolver, `onInvalid`, and any toast never fire at all. Use `type="text"` with `inputMode="url"`/`inputMode="email"` (keeps the right on-screen keyboard, no native gatekeeping) and let the Zod schema be the one validator.
- `toastQueue` (`components/ui/Toast.tsx`) is a module-level singleton living outside React, so a toast added in one test outlives that test's unmount and reappears the instant the next test mounts a fresh `<ToastRegionRoot>`. `vitest.setup.ts`'s global `afterEach` calls `toastQueue.clear()` (alongside RTL's `cleanup()`, which Vitest doesn't auto-register the way Jest does) — don't remove either, and don't add a test-local workaround instead.
- An XState v5 guarded-target array (`[{ guard, target }, { target }]`) is only valid as the *value of `on.EVENT`* — it is not a valid value for a `target:` field nested inside one transition config. There's no shared constant to factor this out to for two different events without TypeScript rejecting it against each event's precisely-typed expected shape; write the array inline at each `on.EVENT` key instead (see `narratedPlayerMachine.ts`'s `NEXT_CUE`/`PREVIOUS_CUE`/`REPEAT`/`NARRATION_ENDED` handlers — yes, repeated across `paused`/`playing`/`narrating`). A compound condition (e.g. "due AND auto-pause AND should-await-resume") is multiple guard-array branches combined with `and([...])`, evaluated top to bottom — not a single branch with a composite guard.
- An invoked actor is auto-stopped the instant its owning state is exited, for any reason — that's the entire reason `narratedPlayerMachine.ts` models cancellable async work (narration audio playback) as a `fromPromise` actor rather than an externally-awaited promise. But a transition that *re-targets the same state the actor is already running in* (e.g. `REPEAT` while already `narrating.speaking`) does **not** restart it unless the transition explicitly carries `reenter: true` — XState does not infer re-entry from a same-state target on its own.
- `onDone`/`onError` on an invoked actor are not the same thing as a same-named event on the owning state. `playNarrationAudio`'s `onError` only `raise`s `NARRATION_FAILED` into the machine's own event queue — the actual `speaking → awaitingResume` transition is a normal `on: { NARRATION_FAILED: {...} }` handler on `speaking`, so the row is directly testable by sending `NARRATION_FAILED` manually, without needing a real rejecting promise.
- `narratedPlayerMachine.ts`'s 100ms poll (`pollClock`, a `fromCallback` + `setInterval`) is `invoke`d on the `playing` state itself, not inside `VideoPlayerPort` — scoping it to a state gets free start/stop lifecycle from XState's invoke semantics instead of manual setup/teardown bookkeeping.
- `NarratedPlayerContext.resumeTo` (`"playing" | "paused"`) is not in the plan doc's literal context shape — added because the spec's own transition rows disagree on where "stop narrating" returns to otherwise (a `TICK`-triggered cue always resumes `playing`; an ad-hoc `REPEAT` from `paused` must resume `paused`). Set on every entry into `narrating`, preserved (not reset) if `NEXT_CUE`/`PREVIOUS_CUE`/`REPEAT` re-arm while already `narrating`. `TOGGLE` is the one exception: it always forces `"playing"` regardless of `resumeTo`, because `Space`/`K` is documented as an unconditional play gesture, not a "go back" one.
- `cueToArm()` in `narratedPlayerMachine.ts` anchors `NEXT_CUE`/`PREVIOUS_CUE` off `context.activeCue.startSeconds` when a cue is already armed, not off `context.currentSeconds` — raw playback position hasn't moved while paused or mid-narration, so anchoring on it would re-arm the *same* cue instead of advancing to the next one.
- YouTube's IFrame `onError` numeric code does not flow through `VideoPlayerPort` (its `onStateChange` union has no error member, correct per spec) — it's wired directly from the component layer to `actorRef.send({ type: "PLAYER_ERROR", code })`. `playerErrorCodes.ts` maps the numeric code to this app's own `KnownErrorCode` vocabulary so `toUserMessage()` renders it like any backend error.
- A `<track>` element only attaches to a native `<video>`/`<audio>` element — it cannot be given to the YouTube IFrame API (a cross-origin iframe has no API for accepting an externally-supplied text track). Don't build a hidden dummy `<video>` just to host one; if a WebVTT resource needs surfacing for a cross-origin player, treat it as a separate artifact (e.g. a download link), not a literal `<track>`.
- `@xstate/react`'s `useActorRef(logic, options)` recreates the actor if `logic`'s identity changes between renders (it compares `logic.config`, restoring a persisted snapshot into a *new* actor ref) — it does not ignore a changed first argument the way `useState`'s lazy initializer does. `createNarratedPlayerMachine(ports)` builds a fresh config object on every call, so memoize it (`useMemo(() => createNarratedPlayerMachine(ports), [ports])`) before passing it to `useActorRef`; passing it inline recreates the actor (and restarts every invoked actor, including the poll) on every render.
- `PlayerShell.tsx` is split into an outer component (data fetching via TanStack Query hooks, port lifecycle via a `ref`+`effect`+`state`) and an inner one (`NarratedPlayerInner`, only mounted once both cues and ports are ready) that calls `useActorRef`/`useHotkeys`/`useSelector` unconditionally. This is the general pattern for "a hook needs an async prerequisite before it can run": gate on the prerequisite by mounting a *different* component, not by conditionally skipping the hook call inside one component.
- `ControlBar`/`NowDescribing`/`CueList` each take the actor ref as a prop and call `useSelector(actorRef, ...)` themselves for only the slice of state they need, rather than the parent subscribing once and passing derived props down — this is what keeps a `TICK`-driven re-render (every 100ms while playing) scoped to the one component that actually reads `currentSeconds`, not the whole player tree.
- `components/ui/Slider` has no `getValueLabel` prop — that doesn't exist in this React Aria Components version. A custom value label (e.g. "1.25 times") goes through the `formatValue` prop added to the wrapper, which feeds a children render function on the underlying `SliderOutput` (`({ state, defaultChildren }) => ...`).
- This project has no `@testing-library/jest-dom`. Component tests assert presence/attributes with `.toBeTruthy()`/`.toBeNull()` and direct `.getAttribute()` reads — not `.toBeInTheDocument()`/`.toHaveAttribute()`, which don't exist here and fail with "Invalid Chai property".
- jsdom doesn't implement `Element.prototype.scrollIntoView`; it's stubbed as a no-op in `vitest.setup.ts`. Don't re-stub it locally in a test file.
- Biome's inline suppression comment is `// biome-ignore lint/<rule>: <reason>`, not ESLint's `// eslint-disable-next-line`. The latter is silently meaningless here (Biome is the one lint tool) and won't suppress anything.
- A `refetchInterval` callback that decides "stop polling" by checking `query.state.data` alone never stops on a persistent error — `data` just stays whatever it last was (often `undefined`) forever, so it keeps scheduling another attempt. Also check `query.state.fetchFailureCount > 0` (see `useVideoStatus`) — by the time a fetch settles as failed, `shouldRetry`'s own retry budget is already exhausted, so there's nothing transient left to wait out.
- React's Strict Mode (on by default for the App Router — `next.config.ts` would need `reactStrictMode: false` to turn it off, which this project doesn't) double-invokes every effect in `next dev` (mount → cleanup → mount). A port/resource constructed *asynchronously* inside an effect (e.g. `createYouTubePlayerPort`'s `new YT.Player(...)` only runs after `loadIframeApi()`'s promise resolves) must check a `destroyed`-style flag *inside* that deferred callback, not just in the synchronous cleanup — otherwise the phantom first mount's cleanup runs before the construction was even scheduled, does nothing, and that deferred construction fires anyway once the promise settles, racing the real mount's own construction into the same DOM node. This is why Watch got stuck on "Loading descriptions…" in dev only (production doesn't double-invoke effects).
